# U0.2 data audit

Tasks: 279. Generated by `uv run utrack data audit`.

## 1. Schema as found

plan_a.md section 1.2 describes a prior schema (nested `task_metadata`, a `showcase` object, documents embedded per task, `annotations.gt_evidence`). The released Hugging Face configs do not match that prior: fields are flat on the task record, and document content/role/subtype live in two separate configs (`documents`, `task_documents`) joined by `document_id`. See `src/utrack/data/schema.py` for the typed version this audit validated against.

**`tasks` fields:** `benchmark_id`, `document_ids`, `entity_name`, `entity_type`, `frequency`, `future_timestamps`, `future_values`, `gt_evidence`, `history_timestamps`, `history_values`, `labels_public`, `origin`, `prediction_length`, `profile_details`, `profile_id`, `profile_name`, `raw_task_path`, `reasoning_hops`, `seasonal_period`, `split`, `target_description`, `time_series_variable`

**`documents` fields:** `document_id`, `raw_document_path`, `roles`, `subtypes`, `task_ids`, `text`

**`task_documents` fields:** `benchmark_id`, `document_id`, `rank`, `raw_document_path`, `role`, `subtype`

**Schema quirk found in U0.2:** `seasonal_period` is inconsistently typed across tasks: 165 tasks are `str`, 114 tasks are `int` (e.g. `"1h"` alongside a bare integer count of periods like `7`). Stored as `str | int | None` in `schema.py`, cast to string in `task_index.parquet` for a uniform column type.

## 3. Does stored document order reveal role?

Yes, fully. In all 279 tasks, sorting `task_documents` rows by `rank` puts every supporting document before every distractor document (279/279 tasks match this pattern exactly). Distractor subtype is not shuffled either: within the distractor block, subtype follows one of two fixed patterns:

- 240 tasks: `confounder > noisy > timeseries > profile > temporal`
- 39 tasks: `confounder > noisy > timeseries > profile > temporal > confounder > noisy > timeseries > profile > temporal > confounder > noisy > timeseries > profile > temporal > confounder > noisy > timeseries > profile > temporal > confounder > noisy > timeseries > profile > temporal`

**This confirms the plan_a.md 1.2 hypothesis, and more strongly than stated:** rank reveals distractor subtype, not just supporting-vs-distractor role. Any code that renders documents into a prompt must shuffle first (already the stated default, plan_a.md 5.2.7 and Decision G).

## 5. Corrections to plan_a.md

- Section 1.2's field list (`task_metadata`, `showcase`, nested `documents`, `annotations.gt_evidence`) does not match the released schema; see section 1 above for what was actually found.
- Section 1.3's `task_42` figures (156 history points, 100-step horizon, 38 documents: 13 supporting / 25 distractor, bug window 2025-10-12 to 2025-11-03) are confirmed exactly against the loaded data. The stated averages are confirmed to within rounding: bug window 833.9 (stated ~834), rest of history 437.8 (stated ~444, off by ~1.4%), true future 464.7 (stated ~465).
- Section 1.2's 'about 37 to 40 Markdown documents' per task undersells the spread: the loaded corpus ranges 30 to 74 documents per task (median 37). Distractor count is always exactly 25 (5 subtypes x 5, verified above), so all of the variation is in the supporting count.
